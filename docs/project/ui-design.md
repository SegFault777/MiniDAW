# UI 설계: Logic Pro와 Ableton Live에서 배운 것

MiniDAW의 화면은 두 제품을 **비교해서 장점은 받아들이고 단점은 피하는** 방식으로 설계했습니다. 어느 쪽도 그대로 따라 하지 않았습니다.

## 1. 비교

| 주제 | Logic Pro | Ableton Live | 장점 | 단점 |
| --- | --- | --- | --- | --- |
| **전체 구성** | 편곡 영역 + 인스펙터 + 믹서 + 여러 편집기 창이 한 화면에 | 두 화면(Session / Arrangement)을 전환 | Logic: 한 곳에서 맥락이 이어짐 / Live: 단순함 | Logic: 처음 보면 빽빽하고 창이 많다 / Live: 화면을 오가야 해서 맥락이 끊긴다 |
| **트랙 머리** | 큰 아이콘, 이름, M/S/R, 슬라이더 | 아주 단순한 이름 + 색 + M/S | Logic: 정보가 많다 / Live: 깔끔하고 색으로 구분된다 | Logic: 좁은 화면에서 답답 / Live: 볼륨과 팬이 머리에 없다 |
| **리전(클립)** | 이름 띠 + 파형, 선택 시 강조 | 색칠된 클립, 이름 띠 | 둘 다 한눈에 구분된다 | Logic은 작은 글씨가 많다 |
| **브라우저** | 왼쪽 라이브러리(소리 모음)와 별도 루프 브라우저 창 | 항상 왼쪽에 있는 **통합 브라우저**(소리, 이펙트, 악기, 샘플, 검색) | Live: 검색과 **드래그앤드롭**이 빠르다 | Logic: 창이 여럿이라 찾기 번거롭다 |
| **이펙트 체인** | 채널 스트립의 인서트 슬롯 + 별도 플러그인 창 | 아래 패널의 **가로 장치 체인**(카드마다 노브가 바로 보임) | Live: 신호 흐름이 눈에 보이고 창이 필요 없다 | Logic: 노브를 보려면 창을 열어야 한다 |
| **믹서** | 정교한 채널 스트립 | 단순한 믹서(스트립이 작다) | Logic: 완성도 | Live: 정보가 적다 |
| **편집기** | 피아노 롤, 스텝 시퀀서, 오토메이션 등 모두 강력 | 클립 뷰에서 간단히 | Logic: 깊이 | 둘 다 학습 필요 |
| **트랜스포트와 표시** | 중앙 **LCD**에 위치, 시간, 템포, 박자 | 가장 위 줄에 작게 | Logic: 한눈에 읽힌다 | Live: 작아서 눈에 덜 띈다 |
| **도움말** | 퀵 헬프 창(옵션) | 화면 구석의 **Info View**(마우스를 올리면 설명) | Live: 항상 켜져 있어 배우기 쉽다 | Logic: 켜야 보인다 |
| **룩** | 어두운 회색, 파란 강조 | 밝은 회색, 노란 강조, 평면적 | | 둘 다 개성이 뚜렷해 그대로 따라 하면 닮아 버린다 |
| **아이디어 검증** | 편곡을 바로 쌓는다 | 클립 런처로 즉흥적으로 시도한다 | Live: 아이디어 스케치에 강하다 | Live: 세션 뷰를 따로 배워야 한다 |

## 2. MiniDAW의 결정

| 결정 | 받아들인 것 | 피한 것 |
| --- | --- | --- |
| **화면 하나, 탭으로 전환하는 아래 패널** (Mixer, Inspector, Devices, Piano Roll, Step Sequencer, Drummer, Automation) | Logic의 "한 화면에서 맥락 유지" | Logic의 창이 많은 구조, Live의 화면 전환 |
| **오른쪽 통합 브라우저** (루프, 악기, 이펙트 + 검색 + 드래그앤드롭) | Live의 통합 브라우저와 드래그앤드롭 | Logic의 창이 흩어진 구조. 위치는 일부러 **오른쪽**: 왼쪽은 트랙 머리가 쓰고, 타임라인 원점이 안 움직인다 |
| **Devices 탭 = 가로 카드 체인 + 노브** | Live의 장치 체인(신호 흐름이 보임, 창 불필요) | Live의 단순한 믹서 대신 Logic처럼 믹서 탭도 따로 둔다 |
| **중앙 LCD 트랜스포트** (마디.박.틱, 시간, 템포, 박자) | Logic의 가독성 | Logic의 모양: 둥근 알약 모양에 청록/주황 두 색으로 구분 |
| **트랙 높이 3단계** (Compact / Normal / Tall) | 둘 다 가진 기능. Tall은 팬까지 보여 Logic의 정보량을, Compact는 Live의 간결함을 준다 | |
| **트랙 머리 왼쪽 색 띠, 색칠한 리전** | Live의 색 구분 | 큰 아이콘(좁은 화면에서 무겁다) |
| **상태 표시줄 도움말** (마우스를 올리면 사용법) | Live의 Info View, 하지만 항상 켜 둔다 | 별도 창이나 설정 |
| **인스펙터** (트랙과 리전의 속성) | Logic의 인스펙터 | 항상 열린 패널 대신 **탭**이라 좁은 화면을 덜 먹는다 |
| **슬레이트 + 청록 룩**, 평면적이고 둥근 모서리 | | 두 제품의 배색과 형태를 닮게 하지 않는다 |
| **믹서 채널 스트립의 이름 칩이 맨 위**(Logic은 아래) | | 위쪽에 두어 큰 화면에서도 어느 트랙인지 바로 보이게 |
| **드래그 중 이름표가 커서를 따라다닌다** | 시각적으로 무엇을 끌고 있는지 확인 | |

## 3. 원칙 (이후 화면을 바꿀 때도 지킨다)
1. **한 화면 원칙**: 새 기능을 위해 새 창을 만들지 않는다. 아래 패널의 탭이나 대화상자로 해결한다.
2. **보이는 것이 곧 조작**: 값은 그 자리에서 끌어서 바꾼다(노브, 슬라이더, 점). 숫자를 쳐서 바꾸는 것은 대화상자에서만.
3. **색은 의미**: 트랙 색은 리전과 믹서의 이름 칩, 노브 호에 이어진다. 청록은 "지금 활성"(재생, 선택, 포커스), 주황은 "주의/템포", 빨강은 "녹음".
4. **마우스를 올리면 설명한다**: 새 컨트롤에는 상태 표시줄 문구를 단다(`hintFor`).
5. **느린 것은 보이게**: 플러그인 검색처럼 오래 걸리는 일은 백그라운드에서 하고 끝나면 알린다.
6. **되돌릴 수 있어야 한다**: 모든 편집은 `Ctrl+Z`로 되돌릴 수 있다.

## 4. 아직 가져오지 못한 것
- **세션 뷰(클립 런처)**: Live의 가장 큰 강점이지만 엔진에 "클립을 박자에 맞춰 시작/중지"하는 기능이 필요하다. [로드맵](roadmap.md) 참고.
- Logic의 **스마트 툴**(마우스 위치에 따라 도구가 바뀜): 지금은 도구가 하나(포인터)이고 위치로 동작이 정해진다.
- **트랙 스택(폴더)**, **플렉스 타임 편집기**.
